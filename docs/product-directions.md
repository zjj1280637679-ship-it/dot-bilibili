# 产品方向：效率与交互

本文件是后续产品合同，不扩大 0.3.0 已验收能力或权限。目标是先交付可用首版，再分阶段补齐业务范围；不是宣称全部 122 项已经完成。

## 三条后端路线互补

| 路线 | 产品重点 | 体验原则 |
| --- | --- | --- |
| 独立接口连接器（直接接入） | **自动性，关键词：效率** | 在明确授权和有界预算内减少重复操作，稳定完成任务；遇到阻塞或结果未知时安全停止。 |
| 浏览器桥接（网页控制） | **人机互助，关键词：交互** | 当前目标和状态可见，动作预览可解释，支持用户介入、接管和校验后续行。 |
| 客户端内部控制器（未来） | **人机互助，关键词：交互** | 面向客户端的可见控制与上下文交接，遵守与网页路线一致的授权和安全边界。 |

三条路线不是互相替代的成熟度阶梯。后端选择、自动化程度、交互模式是独立维度：网页流程也能在授权范围内自动执行；直接连接器也应允许人工确认或接管。不能把每一步都强制手动，也不能把一次请求解释为无限自主权限。

## 统一合同，不统一所有体验

- 保持稳定的统一语义 API、类型化输入输出及明确的能力声明；后端不能悄悄扩大范围或隐式切换到需要新权限的路线。
- 统一表达状态、错误、覆盖范围和下一步建议；交互提示与执行策略可以不同，但必须置于类型化合同之后，不能绕过合同。
- 结果未知必须明确返回，不自动重试、不换调用标识重发；状态查询不能被当作继续执行。恢复前先核对既有结果和授权。
- 自动化预算涵盖时间、调用次数和任务范围。批处理、缓存仅作为未来候选能力：必须有界且获授权，缓存需有新鲜度与失效规则，不扩大数据访问范围。

## 未来验收方向（尚非已实现承诺）

### 直接接入：以效率衡量自动性

拟记录端到端延迟分布（例如 p50/p95）、每个已完成任务的调用次数与成本、授权范围内的完成任务数/完成率，以及阻塞识别后安全停止的比例和耗时。统计应注明工作负载、样本量、失败和未知结果；不能仅展示成功样本或用吞吐量掩盖错误。

延迟、调用预算、超时及批量上限由工程验证设定并按版本记录；它们不是平台官方限额或性能保证。当前没有直接接口路线的实测性能数字。

### 网页与客户端：以交互衡量人机互助

拟提供可见的当前目标、进度与状态，以及可解释的动作预览；支持中断、人工接管和恢复。恢复前重新校验目标、页面或客户端上下文、授权、结果新鲜度及未决动作，不能从陈旧上下文盲目继续。

拟记录目标/状态展示完整率、预览与实际动作的一致率、中断响应时间、接管成功率、恢复前上下文校验覆盖率，以及用户完成任务所需的介入次数。所有指标先定义采样与通过条件，再实测；不虚构数值，也不把“零介入”设为唯一成功标准。

## 0.3.0 现状与缺口

**已支持：**可信浏览器宿主驱动的 Python façade（`search_read`、`status`），以及五项只读原语组成的有界工作流：公开搜索、读取可见搜索结果、从新鲜结果精确打开视频、读取可见视频元数据、读取当前视口相交的公开评论线程。关闭评论步骤为四步，开启为五步。状态查询不新增平台操作；未知结果不自动重发。使用依赖宿主配置和并发 dispatcher，不是独立无人值守驱动。

五项原语已完成本阶段 5/5 有界严格验收；总体仅覆盖已盘点的 5/122。新流程未验证正向评论正文读取或完整评论分页，空评论视口不等于没有评论。范围和证据以 [README](../README.md)、[当前 AI API 用法](ai-tool-usage.md) 和 [五项验收](milestone-five-acceptance.md) 为准。

**待建设、待验收：**独立直接接口连接器、客户端内部控制器、用户可见的交互面板、完整的预览/中断/接管/恢复体验，以及上述指标采集与报告。目前不能声称已有 UI 仪表盘、聊天原生工具自动注册，或独立直接 API 已经可用。未来路线须先补合同与授权边界，再实现和验收，不借已有浏览器验收为新路线背书。

## 隐私与发布边界

后续证据和指标只保留必要的去标识信息，不把凭据、Cookie、私信、运行数据库或原始浏览器回执带入公开交付。公开发布须经过源码、许可与数据最小化审查；这份方向说明不授予额外账号访问或操作权限。
